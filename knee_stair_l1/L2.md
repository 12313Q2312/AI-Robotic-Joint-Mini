# Knee stair assist, layer 2

Simulation only. Synthetic intent. Not a human subject, not EMG, and not a fall-prevention result. The 24 Nm PID limit is unchanged. Controller gains are unchanged. Metric definitions are unchanged.

Layer 1 remains the nominal 30-seed study in `data/verification/knee_stair_l1/`. This file is the layer 2 record: signal freshness, three extra intent scenarios, the latency sweep after freshness, and the default-controller decision.

## Signal freshness

Intent and sensor samples carry a production timestamp. The supervisor compares `now - packet_time` with `safety.freshness_threshold_s` (0.05 s). An age must exceed that threshold by more than 1 ns before it counts as stale, so a packet that is exactly one 5 ms step past a 50 ms hold is still fresh. Receipt time is a separate clock and still drives sensor dropout (0.04 s) and command timeout (0.05 s).

`safety.stale_safe_duration_s` is 0.20 s. The stale timer starts on the first stale evaluation and clears on the first evaluation where both packets are fresh. There is no separate count threshold; duration is the configured persistence.

Returning from DEGRADED requires both packets to stay fresh for `fresh_recover_duration_s` (0.10 s). A shorter fresh gap does not return to NORMAL, so an on/off age around the threshold does not chatter. The ROS node reads `header.stamp` as the source time. A missing stamp, a zero stamp, or a stamp further in the future than `stamp_future_tolerance_s` (0.02 s) is over-age. Receipt time is not the packet time.

## State machine

Rank, highest first:

| Rank | State | Torque | Latch |
|---|---|---|---|
| 5 | E_STOP | 0, passive damping | Until `reset()`. Non-finite sensor, intent, or command. Does not rewrite `/joint/safe_target_angle`. |
| 4 | SAFE_HOLD | 0, passive damping | Until `reset()`. This is the stale-signal safe state. |
| 3 | DAMPING_ONLY | Viscous command, limit 8 Nm | Not latched. Receipt gap or command timeout. |
| 2 | DEGRADED | Cap 0.5 × 24 Nm = 12 Nm, slew 200 Nm/s into and out of that cap | Not latched. Clears only after 0.10 s of continuous fresh packets. |
| 1 | LIMITED_ASSIST | Command clamped to 40 Nm | Not latched. Finite command outside the limit. |
| 0 | NORMAL | Command unchanged | — |

Transitions:

- Fresh packets, finite, in range, recent receipt: NORMAL.
- Command outside ±40 Nm, packets fresh: LIMITED_ASSIST.
- Intent packet stale, sensor packet stale, or both, and the stale timer is still under 0.20 s: DEGRADED. Torque is limited to ±12 Nm. If the previous output was outside that cap, it moves toward the cap at no more than 200 Nm/s. A fresh pair does not leave DEGRADED until that freshness has lasted 0.10 s. The way back to NORMAL or LIMITED_ASSIST uses the same slew. No reset is required. `clamp_actuator_torque` still limits whatever this state emits to ±24 Nm.
- The same staleness still present 0.20 s after the timer started: SAFE_HOLD. Later fresh packets stay in SAFE_HOLD until `reset()`.
- Sensor receipt older than 0.04 s, or command receipt older than 0.05 s: DAMPING_ONLY, unless a higher state is already active. The next timely receipt leaves DAMPING_ONLY. Prolonged dropout also keeps the packet stale, so the stale timer can still move DAMPING_ONLY to SAFE_HOLD.
- Non-finite sensor, intent, or command: E_STOP. It stays above SAFE_HOLD. `reset()` clears both latches.

`/joint/safety_state` stays publish-only.

Fault injection covers stale intent, stale sensor, intermittent staleness that must not latch, recovery from DEGRADED without reset, prolonged staleness into latched SAFE_HOLD, clamp of an over-limit command while DEGRADED, and E_STOP still holding the legacy angle.

## Intent scenarios

All four use the same seed draws as layer 1. The new three change the reference at mid-move:

- `sudden_change`: reference jumps back to the start angle and velocity becomes 0.
- `mid_stop`: reference freezes halfway and velocity becomes 0.
- `reverse`: reference moves from the halfway angle back to the start over the remaining half of the move.

## Latency sweep

A packet is stale only when its age is greater than 0.05 s, so the 50 ms step stays NORMAL. The first step that exceeds 0.05 s is 55 ms. That is where the steady state leaves NORMAL. The first grid point whose steady state leaves NORMAL is 55 ms, not 50 ms. That matches the threshold: age must be greater than 0.05 s, and 50 ms of hold is exactly 0.05 s. From 55 ms upward the steady mode is SAFE_HOLD, because the 0.20 s latch occurs inside the 2 s trial and covers most of the steady window. The sweep marks those points failed because the supervisor left NORMAL. Torque-RMS reduction CIs stay above 0 there: the trial still assists before the latch. That leftover reduction is not evidence that a 55 ms stream is acceptable.

## Default controller

`default_controller` is `assist_policy`. Admittance is promoted only if, on sudden_change, mid_stop, and reverse, both primary metrics have a 95% CI of (admittance reduction − AssistPolicy reduction) entirely above 0.

| Scenario | Torque RMS, admittance minus policy | Positive work, admittance minus policy |
|---|---|---|
| sudden_change | 0.218846 [0.163606, 0.274086] | −0.624003 [−0.719291, −0.528714] |
| mid_stop | 0.141393 [0.088780, 0.194006] | −0.481813 [−0.561159, −0.402467] |
| reverse | 0.265605 [0.208635, 0.322575] | −0.491692 [−0.572871, −0.410513] |

Torque RMS favours admittance. Positive work favours AssistPolicy, and that CI excludes zero. The rule needs both, so the default stays AssistPolicy. The comparison still runs OFF, admittance, and AssistPolicy.

## Limitations

- This is a software loop. It does not certify ROS 2, Webots, mechanical safety, or measured energy savings.
- Admittance is still behind AssistPolicy on positive work, and the two are close on nominal torque RMS. Gains were not tuned to change that. `default_controller` stays `assist_policy`.
- The synthetic human is a bounded PD tracker of a known reference. Sudden, stopped, and reversed references are still predictable tracking tasks. Human-model mismatch and motions that are not a reference trajectory are a later layer, L3. This layer does not claim that limitation is closed.
- Legacy C++ controllers do not use `clamp_actuator_torque`. That is issue #11, not this layer.
- The 15 Nm interaction line is a design assumption, not a comfort study.
- Full per-step raw JSON is a CI artifact (`knee-stair-l2-metrics-raw`), not a committed file.
